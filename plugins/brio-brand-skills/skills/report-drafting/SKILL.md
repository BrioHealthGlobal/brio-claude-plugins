# Report Drafting

Draft professional reports for M&E, program evaluation, 360-degree
feedback, org assessments, and grant-related deliverables. Outputs are
structured, evidence-grounded, and ready for stakeholder review.

## Ground rules
Always surface data limitations explicitly — never bury caveats.
Distinguish clearly between measured findings and inferred conclusions.
Do not overstate statistical significance. Flag missing data as a gap,
not something to fill with assumptions.

## Process

### Step 1 — Clarify scope
If not already given, ask: "What type of report, who's the primary
audience, and what's the source material — do you have data to paste, a
file, or should I draft from a description?" Wait for the response.

### Step 2 — Confirm structure before drafting
Present the proposed report outline (sections + one-line description
each). Ask: "Does this structure work, or do you want to adjust before I
draft?" Wait for confirmation.

### Step 3 — Draft
Apply these defaults unless the user specifies otherwise:
- Executive summary first (max 1 page): findings, implications,
  recommendations
- Lead each section with the conclusion, then evidence
- Use tables for any comparison with 3+ items
- Use plain language — define any technical terms on first use
- Flag data gaps or caveats explicitly, don't bury them

### Step 4 — Methodology note (if applicable)
If the report involves survey instruments:
- Note the instrument and its validation status
- Flag any sample size limitations
- Do not overstate statistical significance

### Step 5 — Return output
1. Full draft
2. List of any assumptions made
3. Flagged gaps: "I assumed X — confirm or provide actual data"

### Step 6 — Save
Ask the user where to save the final draft.
